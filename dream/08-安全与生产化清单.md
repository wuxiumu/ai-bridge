# 08｜安全与生产化清单

本文件把 `ai-bridge/node.md` 的“Production-ready / HTTPS Ready”落到可执行的安全与运维检查项。

## 8.1 密钥管理

- `.env` 仅存在于服务器/部署环境；仓库只提供 `.env.example`
- 不在日志中打印完整 Key（最多输出 hash/后 4 位用于排错）
- 若使用 Docker：
  - 优先用环境变量或 secret 挂载
  - 避免把 `.env` bake 到镜像

## 8.2 鉴权与访问控制

- 网关必须启用鉴权（`master_key`）
- 生产建议：
  - 只允许从可信源访问（IP allowlist / 内网 / Tunnel）
  - Nginx 层加基础访问控制（如仅允许特定路径暴露）

## 8.3 HTTPS（强烈建议）

三种典型方式：

- Nginx TLS 终止（最常见）
- Cloudflare + 回源 HTTP（适合快速上线，但需控制回源访问）
- 直接在网关进程层做 TLS（不优先，维护成本更高）

## 8.4 审计与合规（最低要求）

- 记录：谁（客户端标识）在什么时候调用了哪个模型、结果状态、耗时
- 对敏感内容：
  - 默认不落盘请求体（除非显式开启并告知风险）
  - 如需排障，建议只采样并做脱敏

## 8.5 生产化运维清单（上线前）

- 端口与防火墙：仅开放必要端口（优先只对外开放 443）
- 进程守护：Docker 重启策略或 systemd
- 资源限制：CPU/内存、并发控制
- 日志轮转：避免磁盘打满
- 备份：配置与关键日志（如需审计）备份策略
