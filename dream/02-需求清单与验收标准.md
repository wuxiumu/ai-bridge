# 02｜需求清单与验收标准

本文件将 `ai-bridge/node.md` 中的“核心卖点/功能设计/爆款关键点”转成可落地的需求条目与验收标准。

## 2.1 MVP（当前阶段：基于 LiteLLM Proxy）

### R1｜OpenAI Compatible API

- **说明**：对外提供 OpenAI 风格接口，由 LiteLLM Proxy 承载。
- **验收**
  - `GET /v1/models` 返回模型列表
  - `POST /v1/chat/completions` 可完成对话请求
  - 客户端仅需配置 `Base URL` 与 `API Key` 即可调用（示例见 `09-README 与使用示例规范.md`）

### R2｜多模型支持（静态配置）

- **说明**：在 `config.yaml` 中声明多个 `model_name`，对外以该名字调用。
- **验收**
  - 在 `config.yaml` 新增一个模型条目后，无需改代码即可调用
  - 文档明确“模型名与上游模型名”的映射关系

### R3｜脚本一键启动/停止/重启

- **说明**：MVP 以脚本方式运行服务，适配 Linux/macOS。
- **验收**
  - `ai-bridge/litellm-gateway/start.sh` 能启动服务并写入 PID
  - `stop.sh` 能停止并清理 PID
  - `restart.sh` 能完成重启
  - 日志输出到 `ai-bridge/litellm-gateway/logs/`

### R4｜Dify 可接入

- **说明**：作为 Dify 的自定义 OpenAI 兼容提供商使用。
- **验收**
  - 文档提供 Dify 配置三要素：`Base URL`、`API Key`、模型名
  - Dify 发起请求后可在网关日志中看到对应请求记录

## 2.2 产品化（目标：开源“有产品感”的 AI Gateway）

### R5｜Docker Compose 一键部署

- **说明**：`docker compose up -d` 即可运行（含网关、反代、可选监控组件）。
- **验收**
  - 在干净环境中按文档可部署成功（含 `.env.example`）
  - 具备健康检查（容器/HTTP）

### R6｜多 Provider 支持

- **说明**：OpenAI/Claude/Gemini/DeepSeek/Azure 等通过配置接入。
- **验收**
  - 至少 2 个不同 Provider 的模型能同时在 `/v1/models` 暴露
  - 配置方式统一，密钥仅通过环境变量注入（不写死在仓库）

### R7｜Key 自动轮换（Rotation）

- **说明**：同一 Provider/同一能力下，支持多 Key 分摊请求。
- **验收**
  - 可配置轮换策略（至少：随机/轮询二选一）
  - 单个 Key 失败/被限流时可自动切换到其它 Key（见 R8）

### R8｜Failover（关键卖点）

- **说明**：失败时自动降级或切换备份（Key 或 Model）。
- **验收**
  - 上游返回可重试错误（如 429/5xx/timeout）时触发切换
  - 可配置 `primary -> fallback`（例如 `gpt-4o -> gpt-4o-mini`）
  - 有可观测记录：每次切换记录原因/目标

### R9｜日志与用量统计（Token Tracking）

- **说明**：统计请求量、Token 用量、模型分布（至少能落地到日志/可导出）。
- **验收**
  - 每次请求日志包含：时间、模型、状态码、耗时、上游、（可选）token 使用
  - 能按天滚动（log rotate）或输出到标准输出供容器采集

### R10｜Rate Limit

- **说明**：按客户端/Key/路径/模型维度做限流（先在反代层落地也可）。
- **验收**
  - 超限返回明确错误（429）
  - 限流策略可配置并可回滚

### R11｜HTTPS 与可选 Cloudflare Tunnel

- **说明**：生产默认 HTTPS，对外可通过 Cloudflare Tunnel 暴露服务。
- **验收**
  - HTTPS 终止配置有文档与示例（Nginx）
  - Cloudflare Tunnel 配置为可选项，不强依赖
