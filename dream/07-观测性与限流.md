# 07｜观测性与限流

本文件覆盖 `ai-bridge/node.md` 中的：日志统计、Token 用量、Rate Limit，并给出“先落地再增强”的路径。

## 7.1 日志（最低要求）

### 访问日志建议字段

- 时间戳
- 请求路径（如 `/v1/chat/completions`）
- 客户端标识（若有：IP / API Key 哈希 / 业务方 ID）
- 模型名（外部 + 内部）
- 状态码
- 耗时（ms）
- 上游 Provider
- 错误类型（timeout / rate_limited / upstream_5xx 等）

### 输出位置

MVP（脚本）：

- 文件：`ai-bridge/litellm-gateway/logs/`

产品化（容器）：

- 优先输出到 stdout/stderr（便于 Docker/日志系统采集）
- 或挂载卷写文件并配合 logrotate

## 7.2 Token 用量统计（阶段性）

### MVP 目标

- 先确保“每请求可定位 + 可统计请求量/错误率”
- Token 统计若无法稳定获取，可先作为可选项，不阻塞发布

### 产品化目标

- 输出至少三个维度的聚合：请求数、token 用量、模型分布
- 可选对接：Prometheus（指标）或简单 CSV/JSON 导出

## 7.3 Rate Limit（限流）

### 快速落地（推荐先在 Nginx 层）

优点：简单、稳定、对网关实现无侵入。

常见维度：

- 按 IP
- 按路径（chat/completions 比 models 更重）
- 按并发/请求速率

### 产品化增强（网关层）

- 按 `Authorization`（master key / 子 key）维度
- 按模型维度（贵模型更严格）
- 结合用量（token）做配额

## 7.4 健康检查与告警（建议）

- HTTP 探活：`GET /v1/models`（轻量）
- 指标（可选）：错误率、429 比例、P95 延迟、Failover 次数
